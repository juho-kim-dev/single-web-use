# Single Web Use (SWU)

**AI가 웹 화면을 관찰하고, 지원하는 대상을 조작한 뒤 결과를 확인하도록 돕는 브라우저 상호작용 프레임워크입니다.**

[English](README.md) · [작성자](https://github.com/juho-kim-dev)

관찰과 클릭 사이에 대상이 움직이거나 페이지가 바뀔 수 있고, 입력 전에 요청이 취소될 수도 있습니다. SWU는 화면 관찰, 대상 확인, 입력 전달, 결과 확인을 구분해 호출자가 이 상태를 판단할 수 있도록 합니다.

AI 보조로 브라우저 어댑터, 공통 관찰·실행 모델, CLI, 상태 검사와 선택한 웹 작업의 검증을 개발했습니다.

## 현재 구현 범위

| 구성요소 | 현재 상태 |
| --- | --- |
| Obsidian 웹뷰 어댑터 | 페이지 관찰과 지원 조작의 주 개발·검증 환경 |
| CLI | 명령 조회, 페이지 상태 읽기, 지원 동작 요청의 현재 입구 |
| 공통 검사 | 문서·URL·대상 상태, 취소 여부, 실행 전후 관찰 |
| Chromium 확장 | 페이지 관찰용 개발 어댑터. Comet의 제한된 관찰 기록 있음 |
| MCP·전용 AI 플러그인 어댑터 | 앞으로 추가할 인터페이스. 구현 완료로 제공하지 않음 |

확장의 관찰 결과를 일반 Chrome의 입력 지원 검증으로 확대하지 않습니다. 브라우저와 동작마다 지원 조건이 다릅니다. [영문 구조도](README.md#architecture)의 점선은 계획된 연결입니다.

## 실행 흐름

1. 현재 페이지를 관찰하고 지원하는 대상을 찾습니다.
2. 실행 전에 문서·URL·대상과 취소 상태를 다시 확인합니다.
3. 지원 동작을 수행하고 입력 전달 기록을 남깁니다.
4. 실행 후 관찰로 목표 도달·미도달·미확인을 구별합니다.

클릭 전달 성공과 업무 성공을 같은 것으로 취급하지 않습니다. 실행 후 목표가 보인다는 사실만으로 그 동작이 목표를 만들었다고 단정하지 않습니다.

## 기록이 있는 개발 사례

- 관찰 뒤 대상 위치가 바뀌면 다시 관찰·이동하고 누르기 직전에 재확인합니다.
- 포인터 이동 후 취소된 사례에서는 버튼 누름·뗌이 발생하지 않았습니다. 이미 일어난 포인터 이동까지 없던 것으로 취급하지 않습니다.
- Obsidian에서 일부 실제 사이트의 검색·탐색을, 별도로 Comet에서 페이지 관찰을 확인한 기록이 있습니다.

특정 조건의 개발 사례이며 모든 사이트의 성공률이나 무인 작업의 보장을 뜻하지 않습니다. 현재 공개본에는 이를 재현할 소스·정제한 실행 기록·시험 자료가 아직 포함되어 있지 않습니다.

## 기술과 공개 상태

TypeScript/JavaScript, Node.js, Obsidian Plugin API, Chromium 확장, CLI를 사용합니다. 이 프로젝트의 MCP는 현재 계획 단계입니다.

**2026-10-28 첫 공개본:** 소개·구조·구현 범위를 설명하는 문서 레포입니다. 설치 가능한 릴리스나 SDK는 아직 제공하지 않습니다.

합성 페이지의 짧은 시연, 선별한 어댑터·코어 소스와 실행법, 상태 변경·취소 재현 사례와 외부 코드 출처를 순차적으로 정리할 예정입니다. 개인 탐색 기록·계정 세션·자격증명은 공개 자료에서 제외합니다.
