## Native adapter constraint and current next steps

Official Chrome documentation lists debugger among permissions that cannot be optional: https://developer.chrome.com/docs/extensions/reference/api/permissions. The debugger API supports the Input domain but has attach/detach and policy restrictions: https://developer.chrome.com/docs/extensions/reference/api/debugger. An optional product adapter is not the same thing as optional_permissions:[debugger]; that manifest proposal is invalid. The current build does not add that permission. A future adapter needs a concrete reviewed distribution/installation choice and original-receiver ownership/release tests before actual use.

0.3 implements bounded arrival on the existing reviewed synthetic link path and explicit accumulated reading documents. 0.4 adds durable global pause and preserved pack archive/unarchive/revision restore, with epoch-bound input invalidation and fresh validation after restoration. These do not require introducing native input first. Next open implementation groups from the92-command audit are conditional target-state click and bounded scroll/read progress; tab/surface and acquisition diagnostics; reviewed native pointer/keys/wheel ownership; conditional hover/scroll knowledge, templates/regrounding/migration/recording; separately bounded renderer research. Live usefulness and unavailable-source claims remain separate gates.
